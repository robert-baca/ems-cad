# SFOT EMS CAD System — Technical Overview for Claude

## What This Is
A real-time Computer-Aided Dispatch (CAD) system for Six Flags Over Texas EMS. It has three interfaces:
- **Dispatcher dashboard** — web app for dispatchers to manage units and calls
- **Display board** — wall-mounted read-only view of active calls/units
- **Crew mobile app** — Android (and future iOS) Capacitor app for field medics

## Authentication Flows

### Dispatcher Login
- `POST /api/auth/login` with `{ username, password, role: 'dispatcher' }`
- Password checked against bcrypt hash in-memory
- Returns JWT with `{ role: 'dispatcher', id, name }`

### Crew Login (two-step)
1. `POST /api/auth/crew-login` with `{ username, pin }`
   - Queries Supabase `personnel` table (ems-credentials system)
   - PIN verified with scrypt (`salt:hash` format, 64-byte keylen)
   - Returns pre-auth JWT with `{ personnel_id, name }`
2. `POST /api/crew/select-unit` with Bearer pre-auth token + `{ unit_id }`
   - Returns full JWT with `{ role: 'crew', unit_id, personnel_id, name }`

### Native App Behavior
- `isNative()` in `lib/native.js` detects Capacitor: `!!(window.Capacitor?.isNativePlatform?.())`
- Native app skips role picker — goes straight to crew credentials form
- All fetch calls in native must use `${apiBase()}/...` (not relative `/api/...`)
- `apiBase()` returns `https://cad.sfotems.com/api` on native, `/api` on web

## Real-Time (Socket.IO)

Socket rooms:
- `dispatchers` — all dispatcher sockets
- `crew:${unit_id}` — per-unit crew socket
- `crew_all` — all crew sockets (used for beacon broadcasts)
- `display` — display board sockets

Key events:
- `unit:updated` — unit status/GPS/beacon change → emitted to `dispatchers` + `crew_all`
- `call:created`, `call:updated`, `call:closed` — dispatched to all rooms
- `join:crew` — crew socket joins `crew:${unit_id}` + `crew_all`

## Beacon Feature
Crew can toggle a beacon on their unit. Other crew open "Find a Medic", see units with `beacon_active: true`, select one, and get a compass pointing toward them.

- `PATCH /api/units/:id/beacon` — toggles `unit.beacon_active`, emits `unit:updated` to `crew_all`
- `BeaconMode.jsx` — manages finder/compass views
- Compass uses `navigator.geolocation.watchPosition()` for own position (NOT `myUnit.last_lat` — that comes from async native GPS service and can be stale)
- Device heading: `webkitCompassHeading` on iOS, `(360 - alpha) % 360` on Android
- Arrow angle: `(bearing - heading + 360) % 360`

---

## GPS Tracking
- Native Android GPS background service (Java) posts to `GET /api/gps/update?id=&lat=&lng=&secret=`
- Server updates unit's `last_lat`, `last_lng`, `last_gps_at` in DB and in-memory, broadcasts `unit:updated`
- `GPS_WEBHOOK_SECRET` must match `?secret=` query param on the Tracki/GPS device URL

## Data Model (in-memory, seeded from PostgreSQL)

```js
unit: {
  id, unit_number, unit_name, unit_type,
  status,           // 'available' | 'dispatched' | 'on_scene' | 'transport' | 'out_of_service'
  crew,             // crew member name string
  station,
  tracki_device_id,
  last_lat, last_lng, last_gps_at,
  password_hash,    // legacy unit password (not used for crew login anymore)
  profile,          // JSONB — unit profile info
  beacon_active     // bool — in-memory only, not persisted to DB
}

call: {
  id, call_number, status, call_type, priority,
  location_name, location_lat, location_lng,
  assigned_unit_id,
  received_at, dispatched_at, acknowledged_at, en_route_at,
  on_scene_at, patient_contact_at, cleared_at, available_at, closed_at,
  disposition, close_notes, comments, narrative
}
```

## Android Build

- Package name: `com.sfotems.crew`
- Keystore: `android/app/ems-crew-release.keystore` (alias: `ems-crew`)
- Release builds: `.\gradlew bundleRelease` → `app/build/outputs/bundle/release/app-release.aab`
- Node 22 required (added `"engines": {"node": ">=22"}` in root `package.json`)
- Gradle 9.5 — must use `proguard-android-optimize.txt` (not `proguard-android.txt`)
- App icons generated from `resources/icon.png` via `npx @capacitor/assets generate --android`
- Distributed via Google Play internal testing track

## Build Commands (run from `client/`)
```bash
npm run build              # build React app
npx cap copy android       # copy web assets to Android project
cd android
.\gradlew bundleRelease    # signed AAB for Play Store
.\gradlew assembleDebug    # debug APK for direct install
```

## iOS (Pending — needs Mac)

The web code is already iOS-compatible:
- `webkitCompassHeading` handled in `BeaconMode.jsx`
- `DeviceOrientationEvent.requestPermission()` handled in `BeaconMode.jsx`
- `@capacitor-community/background-geolocation` supports iOS

To add iOS:
1. `npx cap add ios` (requires macOS + Xcode)
2. Add to `Info.plist`: `NSLocationAlwaysAndWhenInUseUsageDescription`, `NSLocationWhenInUseUsageDescription`, `NSMotionUsageDescription`
3. Configure background geolocation plugin for iOS
4. Build with Xcode and submit via App Store Connect
5. Apple Developer Program required ($99/year)
